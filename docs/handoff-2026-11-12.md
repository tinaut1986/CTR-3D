## Result

Old 2DS, production build of 45d582b: 30 fps almost always in a Crash Cove Arcade race; the race start still dips to
25-27 fps. Before: 35-38 ms a frame, 6-20 skipped draws per 64 frames and 0.15-1.5 s stalls.

**Not tested on a New 3DS.** Most changes run there too (XA read-ahead, direct cache flushes, track build at load,
OT walk, `mdlfast`, `skyfast`, `trkraw`); Old-class only: `c3dflush 1`, `kartlod`. One New 3DS race (and a look at
menus) before tagging.

## How to test (what worked this session)

- Build on Windows: devkitPro msys2 `bash -l` with `DEVKITPRO=/opt/devkitpro`, `./build3ds.sh --no-cia [--release]`;
  CIA from WSL: `./package-cia.sh build-3ds[-release]` (makerom is a Linux binary). Check the build succeeded
  before packaging: packaging takes whatever ELF is there.
- Install: curl the CIA to `ftp://<2DS>:5000/3ds/ctr_native/update/dev.cia` with `-Q "+ALLO <size>"` and
  `-Q "-SITE INSTALL /3ds/ctr_native/update/dev.cia"`. A production build needs `dev-ftp.txt` in
  `sdmc:/3ds/ctr_native/` (present on the 2DS). The 2DS was 192.168.1.143, then .144 (DHCP).
- Measure: debug build, `SITE DUMPREQ sampler` before the race, then read `/ctr3ds.log` once afterwards
  ([PACE], [PERF], [SAMPLE], [MODELFRAME], [KARTLOD], [TRKDRAW]). Never poll FTP while the owner plays: each request
  stalls an Old 3DS for 1-2 s. The attract demo races hands-free after ~5 min idle.
- `ctr3d.cfg` is rewritten from memory at every relaunch: an edit over FTP is lost; use a flag file
  (`core1.txt` style) for test switches.
